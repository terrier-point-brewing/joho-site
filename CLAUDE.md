# Joho Brewing Co. — public site

Standing rules for anyone (human or Claude) working on this repo. Read this
before touching styling, content, or the stack.

## Stack

- Next.js (App Router) + TypeScript
- Tailwind CSS v4
- Fully static export (`output: "export"` in `next.config.ts`) — no API
  routes, no server actions, no database
- Fonts loaded via `next/font/google` in `src/app/layout.tsx`

## Brand

Indigo and paper are the foundation. Everything sits on that pairing and
it does the work of feeling settled, printed, a little older than us.

Then two accents, used sparingly enough that they still mean something.
Seal red is the mark of authorship, a single point of red where we have
signed our name, and it stays at or under 5% of a composition. Camphor is
warmth and material, the wood and paper end of the palette. Neither is a
background and neither is a theme. If you find yourself reaching for a
third accent, the piece probably needs less, not more.

Season art brings its own colors and it should. That is the
illustration's business, not the palette's.

## Styling rules (hard rule)

All styling flows through `src/styles/tokens.css`. It is the single
styling entry point and will eventually be regenerated from the brand
guide by another system.

- No raw hex values anywhere outside `tokens.css`.
- No font family names (`Marcellus`, `Lato`) anywhere outside
  `tokens.css` and the `next/font/google` setup in `layout.tsx`.
- No magic numbers (spacing, tracking, animation duration/easing) outside
  `tokens.css` — add a token instead of hardcoding a value in a component.
- Components consume tokens only as Tailwind utilities generated by the
  `@theme` block (`bg-ground`, `font-display`, `tracking-display`, etc.),
  never as inline styles or one-off CSS.

`tokens.css` has two layers and the distinction is load-bearing:

- **Primitives** are the palette as the brand guide names them
  (`--color-indigo`, `--color-vermilion`). They say what a color *is*.
  Components never reference these directly.
- **Roles** say what a color *does* on a given ground — `--color-ground`,
  `--color-surface`, `--color-line`, `--color-line-strong`,
  `--color-display`, `--color-ink`, `--color-ink-muted`,
  `--color-accent`, `--color-on-accent`. Components use only these.

That split is what makes theming work: the dark theme re-points the roles
and nothing else in the app changes. Add a new component by reaching for
a role. If no role fits, add a role, not a raw primitive.

## Theming

Light and dark are both first-class. The dark theme is not an inversion —
it has its own canvas (midnight) and its own accent (vermilion), because
seal red is unreadable on indigo grounds.

The active theme lives in a `data-theme` attribute on `<html>`, set
before first paint by the inline script in `layout.tsx` (see
`src/lib/theme.ts`). It defaults to the system preference and is
overridden by the toggle, which persists to `localStorage`.

- Prefer swapping role variables over writing `dark:` utilities. The
  `dark:` variant exists for the rare case where a swapped variable is
  not enough, such as showing one of two labels.
- `ThemeToggle` deliberately holds no React state. The current theme is
  already on the DOM, so reading it on click avoids both a hydration
  mismatch and a flash of the wrong label.

## Content rules

All copy lives in `src/content/site.ts` as typed constants. Components
take content as props (or import directly from `src/content`) — never
hardcode strings in JSX.

Voice for any copy: plain, warm, image-first. No irony. Minimal use of
dashes, colons, or semicolons.

## Structure

- `src/styles/tokens.css` — design tokens (see above).
- `src/content/site.ts` — all copy.
- `src/components/` — presentational components (`Wordmark`, `Hero`,
  `Footer`, `LegalPage`, `ThemeToggle`, and more as the site grows).
  `Wordmark` is currently styled text standing in for a future SVG
  lockup — keep it isolated so the swap doesn't ripple into callers.
- `src/lib/` — the small amount of non-presentational code. Currently
  just the theme storage key and the pre-paint init script, shared
  between `layout.tsx` and `ThemeToggle`.
- `src/app/` — routes. Pages compose components; keep logic in pages
  near zero.

## Scope

This site stays static until explicitly told otherwise. The future tap
list will read Supabase directly from the client using a public anon
key — never add a custom backend, API route, or server action for it.
